Verified crash facts

The TestFlight app crashes almost immediately on launch on iOS 26 with:

EXC_CRASH (SIGABRT)
objc_exception_rethrow
facebook::react::ObjCTurboModule::performVoidMethodInvocation(...)
React Native 0.81.5
Expo SDK 54
Release/TestFlight build

The Apple crash report does not identify the native module or provide the Objective-C exception reason.

We already performed a TestFlight diagnostic build disabling the module-level expo-notifications setNotificationHandler(...) registration. The app still crashed immediately. That change has since been reverted. Treat that notification-handler hypothesis as ruled out.

We have external evidence from React Native issue #54859 that this crash signature may represent a broader iOS 26 / RN 0.81.5 Release-mode problem in which an Objective-C NSException escaping from a void TurboModule invocation causes a fatal abort. Different native modules may trigger the same underlying crash class.

Therefore, do not assume that one particular dependency is the root cause merely because its stack/API shape looks plausible.
