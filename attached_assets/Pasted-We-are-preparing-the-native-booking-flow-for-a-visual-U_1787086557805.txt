## Fix 1 — Correct appointment type name

Current issue:

SelectDate.tsx has a fallback of:

"Workout for 1"

when appointmentTypeName is not present in the URL.

This is incorrect because the selected appointment type may be Red Light Therapy.

Fix this so the UI always derives the appointment type name from the authoritative booking configuration when possible.

Requirements:

* Do not hardcode "Workout for 1" as a generic fallback.
* Use the selected appointmentTypeID to find the corresponding appointment type from /api/booking/config.
* If the type cannot be resolved, use a neutral fallback such as "Appointment" rather than incorrectly claiming it is Workout for 1.
* Apply the same principle anywhere else in the booking flow where appointmentTypeName is displayed.
* Do not duplicate appointment type definitions.

Verify that:

* Workout for 1 displays correctly.
* Red Light Therapy displays correctly.

## Fix 2 — Preserve selected time when navigating backward

Current issue:

On web:

Select Date
→ Select Time
→ Confirm
→ Back

can cause the previously selected time slot to be lost because selection is stored only in local component state.

Improve this behavior.

The preferred approach is to preserve the selected date/time through the existing route/query state rather than introducing a large global state solution.

For example, if the existing architecture supports it:

Select Time
→ Confirm?datetime=<selected ISO datetime>

or an equivalent route-state mechanism.

Requirements:

* Preserve the exact Acuity datetime value.
* Do not convert it to a display string and then attempt to reconstruct it.
* Do not alter timezone behavior.
* Do not duplicate booking state globally unless necessary.
* If the user changes the date, invalidate/remove the previously selected time.
* If the selected time is no longer available, require the user to choose another time.
* Confirm must always submit the currently valid selected datetime.

Do not implement a complex state-management system for this.
